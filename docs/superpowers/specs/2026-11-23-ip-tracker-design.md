# 접속 국가 집계 대시보드(ip-tracker) 설계

작성일: 2026-11-23

표기: **[결정]** 은 요청자가 대화에서 정한 것, **[제안]** 은 작성자가 판단해 채운 것(요청자가 아직 반대하지 않았을 뿐, 바꿀 수 있음)이다.

## 1. 목적

공공기관 폐쇄망에서 운영 중인 앱 전용 IT 서비스에 어느 국가에서 요청이 들어오는지 집계해 보여준다.

- **1차 수요자(윗선 보고 대상)**: 해외 수요가 얼마나 되는지 숫자로 보고 싶어 한다. 직접 접속하지 않고 보고서로 받는다. 아직 구체적 요구는 없고 "일단 숫자를 보자"는 단계다.
- **2차 수요자(인프라 담당자)**: 해외에서 공격이 들어오는 IP가 있는지 찾고 싶어 한다.
- **3차 기대**: 정상 이용자는 회원번호가 남으므로, 누가 어느 국가에서 접속했는지 추적한다.
- **운영자**: 요청자 본인(응용 담당). 매일 로그를 받아 적재하고 본인 PC에서 본다.

## 2. 단계

세 덩어리를 순서대로 완성한다. **이 문서의 구현 범위는 1단계**이고, 2·3단계는 DB 구조와 화면 확장을 막지 않도록 개요만 적는다. 2·3단계는 착수 전에 각각 설계를 다시 한다.

1. **1단계**: access 로그 적재, 국가별 대시보드, 보고서 내보내기.
2. **2단계**: service 로그·nohup 로그 연동, 의심 IP 화면.
3. **3단계**: 회원번호–국가 추적.

## 3. 목표 / 비목표 / 실패 조건

**목표(1단계)**
- 16대 서버의 access 로그를 적재해 국가별 요청 수와 고유 IP 수를 기간별로 본다.
- 국내도 통계(요청 수, 고유 IP 수)는 남긴다.
- 404를 낸 IP를 따로 세고, 집계에서 제외할 수 있다.
- A4 한 장 보고서를 PDF/인쇄로 내보낸다.
- 적재 후 원본 로그를 지워도 대시보드가 유지된다.

**비목표**
- 실시간 수집, 서버에 에이전트 설치, 자동 수집. 수집은 수동이다.
- 여러 사람이 접속하는 웹 서비스. 본인 PC 전용이다.
- 국내 IP에 대한 개별 요청 보관(통계만).
- 도시 단위 위치 판별(국가 단위만).

**실패 조건(동작해도 실패)**
- 인터넷 연결이 있어야 동작하는 부분이 하나라도 있다(CDN, 온라인 지도 타일, 온라인 GeoIP 조회, 웹폰트 등).
- 형식을 잘못 읽은 채 적재하고 원본을 지워, 데이터를 복구할 수 없게 된다.
- 같은 로그를 두 번 넣어 숫자가 부풀려진다.
- 로그가 쌓일수록 PC 디스크가 감당 못 할 만큼 DB가 커진다.
- 목업과 동떨어진 화면, 또는 90년대 개조식 문서 같은 보고서.

## 4. 제약과 환경

- 폐쇄망 안의 업무용 **Windows 10** PC에서 실행한다. 개발 도구 반입 제한은 없다. 다른 Tauri 프로젝트가 이 PC에서 추가 설치 없이 실행된 적이 있다(WebView2 사용 가능).
- 개발은 인터넷이 되는 Mac에서 하고, GitHub 릴리즈로 Windows 설치 파일을 만들어 반입한다. 요청자가 익숙한 흐름이다.
- **Electron은 쓰지 않는다. [결정]**
- 서버 구성은 Apache–Tomcat이고 Apache가 16대 VM에 있다. 요청은 16대에 분배된다. access 로그에 남는 IP는 실제 사용자 IP다(인프라 담당자 확인).
- 로그는 접근제어 때문에 수동으로 받아온다. 서버에서 `grep` 같은 명령을 실행하고 결과만 받아오는 것은 가능하다.
- 서버에는 약 3개월치 로그가 남아 있고, 지난 것은 `.gz`로 압축돼 있을 수 있다.
- 수집 주기는 당분간 매일이다.
- **개발자는 실제 로그를 볼 수 없다.** access 로그의 정확한 형식(특히 시간 형식)은 아직 확인되지 않았다.

## 5. 만드는 방식

검토한 세 가지:

| 방식 | 내용 | 장단점 |
|---|---|---|
| **A. Tauri 데스크톱 앱** | Rust가 파싱·국가 판별·SQLite 적재, 화면은 웹 기술 | 파일 끌어다 놓기·원본 삭제 등 PC 작업이 자연스럽고 대용량도 빠름. 익숙한 배포 흐름. 본인 PC에서만 볼 수 있음 |
| B. 단일 실행 파일 + 브라우저 | 같은 코어를 로컬 웹서버로 띄움 | 다른 사람이 접속해 볼 수 있으나, 파일 다루기가 덜 매끄럽고 앱다운 느낌이 약함 |
| C. Python(Streamlit/Dash) | 스크립트 기반 | 빨리 만들지만 대용량 파싱이 느리고 실행 파일로 묶기 어려움 |

**A로 결정. [결정]** 본인이 적재하고 본인 PC에서 보는 도구이고, 윗선은 직접 접속하지 않고 보고서로 받기 때문이다.

세부 기술 선택 **[제안]**:
- 백엔드: Rust, `rusqlite`(SQLite 내장 빌드), `maxminddb`, `flate2`(gz), `chrono`.
- 화면: Vite + React + TypeScript, 차트와 세계지도는 ECharts. 세계지도 GeoJSON과 모든 라이브러리·글꼴은 앱에 내장한다.
- 빌드: GitHub Actions의 Windows 러너에서 Tauri 설치 파일(NSIS)을 만들어 릴리즈에 올린다.
- 화면 글꼴은 Windows 기본 글꼴(맑은 고딕)을 쓴다.

## 6. 1단계 설계

### 6.1 로그 적재

- **입력**: 파일 또는 폴더를 창에 끌어다 놓거나 선택한다. 일반 텍스트와 `.gz`를 모두 읽는다. 폴더는 하위까지 훑는다. **[결정: gz 지원] [제안: 나머지]**
- **파일 단위 [결정: 요청자 확인]**: access 로그는 하루에 한 파일이고 파일명에 날짜가 들어간다. 일정 크기를 넘거나 재기동하면 분할되며 이름 끝에 `_1`, `_2`가 붙는다(요청자 기억 기준, 용량 분할은 드묾). 따라서 한 서버의 같은 날짜에 파일이 여러 개일 수 있고, 이는 정상이다.
- **서버 구분 [제안]**: 16대의 파일명이 같을 수 있으므로, 파일이 들어 있는 바로 위 폴더 이름을 서버 이름으로 쓴다(예: `was01/access_log.2026-11-22`). 서버별 폴더로 받지 않는 경우를 위해, 파일명에서 서버 이름을 뽑는 규칙(정규식)을 설정에 지정할 수도 있다. 미리보기에서 서버 이름을 확인·수정할 수 있다. 서버 이름은 적재 현황("서버 16/16") 표시와 파일 식별에만 쓰고, 집계는 서버 구분 없이 합친다.
- **형식 인식 [결정: 자동 인식 + 직접 지정 + 미리보기 방향에 동의]**
  1. 파일 앞부분으로 Apache 기본 형식(common, combined)과 흔한 시간 형식 변형을 자동 판별한다.
  2. 실패하거나 틀리면 사용자가 Apache `LogFormat` 문자열을 붙여 넣거나 시간 형식을 직접 지정한다. 지정한 값은 저장해 다음 적재에 재사용한다.
  3. 적재 전에 앞 20줄의 파싱 결과(IP / 시간 / 메서드 / URL / 상태코드)를 표로 보여주고, 사용자가 확인해야 적재한다.
- **필요 필드**: 클라이언트 IP, 시간, 메서드, URL, 상태코드. 있으면 응답 크기와 User-Agent도 저장한다.
- **시간대 [제안]**: 로그에 시간대가 있으면 그것을, 없으면 한국 시간(KST)으로 본다. 날짜 경계와 모든 집계는 KST 기준이다.
- **파싱 실패 줄 [제안]**: 건너뛰고 개수를 센다. 실패가 전체의 1%를 넘으면 적재를 확정하기 전에 경고하고 실패한 줄의 예시를 보여준다.
- **중복 방지 [제안]**: 파일 내용의 해시를 적재 이력에 기록하고, 같은 내용의 파일은 건너뛴다. 같은 요청이 여러 서버 로그에 중복 기록되지는 않는다고 본다(요청 한 건은 한 서버에만 감). 여러 서버에 같은 IP가 나오는 것은 합산 후 IP 기준으로 세어 해결한다.
- **이어 쓰는 파일 [제안]**: 당일 로그처럼 아직 쓰이는 파일을 받아와 넣었다가 다음 날 완성본을 다시 넣으면 내용 해시가 달라 중복된다. 이를 막기 위해 파일을 "서버 이름 + 파일명"으로 식별한다. 같은 서버·파일명인데 내용이 다른 파일이 들어오면 "기존 것을 대체 / 건너뛰기"를 묻는다. 대체할 때는 기존 파일이 넣은 데이터만 정확히 지우고 다시 넣는다. 이를 위해 모든 데이터 행에 어느 파일에서 왔는지를 기록한다(6.3 참고). 같은 날짜의 분할 파일(`_1`, `_2`)은 파일명이 다르므로 서로 겹치지 않는 별개 파일로 적재한다.
- **원본 삭제 [결정: 삭제 방향] [제안: 방식]**: 적재 화면에 "적재가 끝나면 원본 파일 삭제" 체크박스를 둔다. DB에 기록이 확정된 파일만 지우고, 실패하거나 건너뛴 파일은 남긴다. 휴지통을 거치지 않고 바로 지운다(디스크 확보가 목적).
- **진행 표시 [제안]**: 파일별 진행률과 결과(적재 줄 수, 실패 줄 수, 해외 건수)를 보여준다. 대용량이므로 한 줄씩 흘려 읽고 화면이 멈추지 않게 한다.
- **소급 적재 [결정]**: 3개월치를 소급하지는 않는다. 많아야 지난 며칠(예: 금·토·일)분을 한 번에 넣는 정도다. 여러 날짜 × 16대 파일을 한 번에 끌어다 놓아 적재할 수 있으면 된다. 서버에 남은 지난 로그가 `.gz`일 수 있으므로 gz 지원은 유지한다.

### 6.2 국가 판별

- 오프라인 GeoIP DB 파일(`.mmdb`)을 앱에 내장한다. **[결정: 오프라인 DB]**
- **DB 선택 [제안]**: DB-IP의 "IP to Country Lite"(mmdb 형식, CC BY 4.0). 계정 없이 받을 수 있고 출처 표기만 하면 재배포할 수 있어 릴리즈에 묶기 쉽다. 앱의 정보 화면과 보고서 하단에 출처를 표기한다.
- **갱신 [제안]**: 설정 화면에서 새 `.mmdb` 파일을 불러와 교체할 수 있다. 화면에 현재 DB의 기준 날짜를 보여준다. 이미 적재한 데이터의 국가는 다시 계산하지 않는다(적재 시점 기준).
- **분류 [제안]**: 한국(KR)은 국내, 그 외 국가는 해외. 사설·내부 대역(10.x, 172.16–31.x, 192.168.x, 127.x 등)은 "내부"로 분류해 국내·해외 집계에서 모두 뺀다(L4 상태 점검 등). 판별되지 않는 IP는 "알 수 없음"으로 두고 해외 집계에 넣지 않되, 건수는 화면에 따로 보여준다.
- 국가 이름은 한국어로 표시한다.

### 6.3 저장(SQLite)

원칙: **모든 IP는 일별 요약으로, 해외 IP만 개별 요청으로** 남긴다. **[결정: 해외만 상세, 국내는 통계]**

| 테이블 | 내용 |
|---|---|
| `ingest_files` | 적재 이력: 서버 이름, 파일명, 내용 해시, 로그 날짜 범위, 줄 수, 실패 줄 수, 적재 시각 |
| `ip_daily` | 날짜 × 파일 × IP별 요청 수, 404 수. 국내·해외·내부 모두. 국가 코드 포함 |
| `country_hourly` | 날짜 × 시간 × 파일 × 국가별 요청 수(시간대 분포용) |
| `foreign_requests` | 해외 IP의 개별 요청: 시간, IP, 국가, 파일, 메서드, URL, 상태코드, 응답 크기, User-Agent |

- 모든 행에 출처 파일(`ingest_files` 참조)을 넣는 이유는 특정 파일분만 정확히 지우고 다시 적재할 수 있게 하기 위해서다. 서버는 파일을 통해 알 수 있다. 화면 집계는 파일·서버를 합쳐서 한다.
- 실제 로그 규모(서버당 하루 줄 수, 하루 고유 IP 수)와 PC 디스크 여유는 확인되지 않았다. 요청자는 소급 범위가 작아 걱정할 수준이 아니라고 봤다. 대신 DB 크기 표시와 오래된 상세 삭제 기능으로 대비한다.
- 고유 IP 수는 `ip_daily`에서 기간 내 IP를 중복 없이 세어 구한다(일·주·월 어느 기간이든 정확).
- "404를 낸 IP"는 선택한 기간 안에서 404가 1건 이상인 IP다.
- User-Agent처럼 반복되는 문자열은 별도 테이블로 빼서 번호로 참조해 용량을 줄인다. **[제안]**
- DB 파일 위치는 앱 데이터 폴더를 기본으로 하되 설정에서 바꿀 수 있다. 화면에 현재 DB 크기를 보여준다. **[제안]**
- 오래된 `foreign_requests`를 지우는 기능(예: N개월 이전 삭제, 요약은 유지)을 설정에 둔다. **[제안]**
- 2·3단계에서 테이블을 추가할 수 있게 스키마 버전과 마이그레이션 구조를 둔다.

위에서 아래 순서:

1. **상단 줄**: 기간 선택(어제 / 최근 7일 / 최근 30일 / 기간 지정), 적재 현황(며칠까지 적재됐는지, 그날 서버 몇 대분이 들어왔는지), "로그 적재"·"보고서 내보내기" 버튼.
2. **제외 스위치**: "404를 낸 IP 제외". 켜면 핵심 숫자·지도·막대·추이·표·보고서 전체에서 해당 IP의 요청이 빠진다. **제외 기준은 선택 기간 안에 404를 한 번이라도 낸 IP다. [결정]** **국내·해외 IP 모두에 똑같이 적용한다. [결정]** 따라서 전체 요청, 국내 고유 IP, 해외 비중도 함께 바뀐다. (목업 문구 "없는 URL만 요청한 IP 제외"는 이 기준에 맞게 고친다.)
3. **핵심 숫자 5칸**: 전체 요청 / 해외 요청(전체 대비 비율) / 해외 고유 IP(국내 고유 IP 병기) / 그중 404를 낸 IP(해외 IP 대비 비율) / 접속 국가 수(신규 국가 수). 직전 같은 길이 기간 대비 증감을 함께 보여준다. "신규 국가"는 직전 같은 길이 기간에는 없었고 이번 기간에 나타난 국가다. **[제안]**
4. **세계지도 + 해외 상위 10개국 막대**: 지도는 요청이 많을수록 진하게, 국가에 마우스를 올리면 요청 수와 고유 IP 수. 한국은 지도 색 계산에서 뺀다(해외 분포가 묻히지 않게). **[제안]**
5. **일별 추이**: 해외 요청 수와 해외 고유 IP 수.
6. **국가별 상세 표**: 국가 / 요청 수 / 해외 중 비율 / 고유 IP / 404 요청 수 / 404를 낸 고유 IP / 최근 접속. 열 제목으로 정렬. 국가를 누르면 그 국가의 IP 목록(IP별 요청 수, 404 수, 처음·마지막 접속)과, IP를 누르면 그 IP의 개별 요청 목록을 본다.
7. **안내사항 [결정]**: 화면에 다음을 적는다.
   - 국가는 IP 주소 기준으로 판별하며 VPN 등으로 실제 위치와 다를 수 있다.
   - "404를 낸 IP 제외"를 켜면, 없어진 주소를 호출하는 구버전 앱 이용자도 함께 빠질 수 있다.
   - 통신사·공용 와이파이처럼 여러 사람이 한 IP를 쓰는 경우, 한 명의 404로 같은 IP의 다른 이용자도 함께 빠질 수 있다.

**"요청 수"와 "고유 IP 수"는 항상 나란히 보여준다. [제안, 목업에서 수용됨]** 한 IP가 대량 요청을 보내면 요청 수만으로는 수요가 부풀려 보이기 때문이다.

숫자는 천 단위 쉼표를 쓰고, 화면 문구는 모두 한국어다.

### 6.6 개발·검증 **[제안]**

- 실제 로그를 쓸 수 없으므로, Apache 형식의 가짜 access 로그를 만드는 생성기를 둔다(국가 분포, 404 비율, 16대 분산, gz 포함). 파서 테스트와 화면 확인에 쓴다.
- 파서는 형식별 단위 테스트를 갖춘다(common, combined, 시간 형식 변형, 깨진 줄, IPv6).
- 폐쇄망 PC에서 첫 실행 때 실제 로그 미리보기가 맞는지 요청자가 확인한다. 안 맞으면 `LogFormat`을 지정해 해결하고, 그래도 안 되면 마스킹한 예시 줄을 받아 파서를 고친다.

## 7. 2단계 개요(이번 구현 범위 아님)

요청자가 설명한 수동 추적 흐름: 의심 IP를 받는다 → access 로그에서 그 IP의 요청을 본다 → 같은 IP로 service 로그를 걸러 시간(`2026-11-23 14:00:03,249` 형식)을 얻는다 → 그 시간으로 nohup 경로의 전체 트레이스 로그(INFO/DEBUG/ERROR)에서 해당 줄과 이후 1~2줄을 본다.

- service 로그는 하루 1GB 안쪽, nohup 로그는 VM당 하루 수 GB다.
- **nohup에서 남길 범위는 해외 IP 건만. [결정]** 국내 IP가 나중에 의심돼도 nohup 내용은 볼 수 없다는 점을 요청자가 알고 선택했다.
- **nohup은 통째로 받아오지 않는다. [결정: grep 방식 동의]** access·service 로그 적재 후, 앱이 해외 IP 건의 시간 목록으로 `grep -A2` 명령(또는 패턴 파일)을 만들어 주고, 요청자가 16대에서 실행한 결과만 받아와 적재한다.
- 의심 표시 기준은 "없는 URL 요청(404)"을 기본으로, 404 비율과 단시간 대량 요청을 더하는 안을 제안한 상태다. 인프라에서 받은 IP 목록을 넣어 조회하는 기능도 필요하다.
- 1단계의 `ip_daily`에 국내 IP의 요청 수·404 수가 있으므로, 국내 IP도 "요청이 비정상적으로 많다 / 404가 많다" 수준의 탐지는 가능하다.

## 8. 3단계 개요(이번 구현 범위 아님)

service 로그에 남는 회원번호와 IP를 연결해, 회원별 접속 국가를 본다. 회원번호가 어느 로그에 어떤 형식으로 남는지는 착수 전에 확인한다.
